# 多 Issue PR 审批

Luke 2026-10-12 要求：一个 PR 可引用多个 Issue；实际合入后关闭全部引用且仍开放的 Issue，尊重 PR 明确声明不关闭的 Issue。

实现范围：
- 解析同仓库 PR 标题/正文中的 Issue 引用，去重并排除 PR 编号和其他仓库链接。
- 审核包携带完整 Issue 集合，每个 Issue 的正文、评论摘要、标签、依赖及暂停状态均从 GitHub 读取。集合需求摘要绑定全部需求，旧策略报告失效。
- 引用但明确声明不关闭的 Issue 只作为需求上下文，不认领、不回写、不修改标签、不关闭；其他开放 Issue 都须满足认领与暂停要求；同一 PR 交付集合中的依赖允许一起交付，集合外未关闭的依赖仍阻断；已关闭 Issue 保留作为需求上下文，不重新打开。
- 非批准终态逐个回写开放 Issue，保留去重与三轮暂停；逐项失败不漏掉其余 Issue，并报告不完整。
- 只在 GitHub 确认 merged 后逐个关闭 Issue、清理状态标签并回读。仅启用 auto-merge 时继续等待；后续扫描恢复未完成的关闭。
- 更新规则、定向回归测试与工具类型检查，构建 controller 安装包。依照既有 A 方案，root-owned 安装由 Luke 在本机终端执行。

#333 的“不关闭也不修改 #301”声明保留。按照 Luke 后续纠正，该 Issue 必须从生命周期写入集合排除；仍完整读取并绑定其需求。不直接批准该 PR，也不以 CI 绿色取代独立审核或迁移证据。
