# 产品设计原则与主要风险

## TL;DR

- 设计优先追求低摩擦、自然表达、克制回应、连续记忆和可信边界。
- 核心风险包括共情同质化、留存衰减、虚假认同、错误记忆、隐私、Voice 成本与情感依赖。
- 风险缓解必须保护用户控制、事实边界和非治疗定位。

## 24. 产品设计原则

1. **先接住，再记录。**
2. **先理解，再追问。**
3. **不急着帮助用户成长。**
4. **像一个存在，但不假装是人。**
5. **有稳定人格，但不经营依赖。**
6. **记忆自然出现，不展示技术感。**
7. **平凡的一天也值得记录。**
8. **不要求打卡，不惩罚中断。**
9. **Journal 是观察，不是事实裁决。**
10. **让用户拥有数据退出权。**
11. **减少输入成本，而不是增加反思任务。**
12. **长期价值必须从第一天就能感知。**

## 25. 主要风险

### 25.1 共情同质化

高质量共情越来越容易被通用模型实现。

应对方向：

- 稳定人格；
- 长期记忆；
- 独特 Journal；
- Daily Session 结构；
- Voice 交互品质；
- 用户长期生活数据积累。

### 25.2 新鲜感后留存下降

用户可能第一次觉得惊艳，但一周后失去动力。

应对方向：

- 晚间固定主循环；
- 低压力通知；
- 一周内出现可靠记忆；
- Journal 回看价值；
- 不制造 Streak 压力。

### 25.3 AI 过度共情或虚假认同

AI 可能无条件认同用户，导致回应不真实。

应对方向：

- 共情感受，不盲目认同事实判断；
- 允许温和表达不同理解；
- 避免夸张赞美；
- 不自动把用户描述成受害者。

### 25.4 错误记忆

长期错误会严重破坏信任。

Internal Core 与 External MVP 都必须：

- 对记忆标置信心；
- 区分事实和推断；
- 定期 Profile Validation；
- 避免低置信度信息进入长期 Profile；
- 从第一条可召回 Memory Claim 开始支持对话内 Memory Correction 与
  Memory Forget Request。

### 25.5 隐私与安全

对话内容高度敏感。

需要重点控制：

- 内部访问；
- 模型供应商；
- 日志；
- 数据保留；
- 账号被盗；
- 删除流程；
- 法律与地区合规。

### 25.6 实时 Voice 成本

Voice Live 可能带来较高模型和语音成本。

需要在 Internal Core 建立成本基线，并在 External MVP 测试：

- 每用户平均日使用分钟；
- 峰值并发；
- 月均模型成本；
- 不同订阅周期的毛利；
- 是否需要合理使用政策。

### 25.7 情感依赖与安全事件

即使产品不定位为 Companion，用户仍可能形成强情感依赖。

从 Core Flow 1A.1 开始必须成立的最小行为边界：

- 清晰非人类身份；
- 不鼓励排他关系；
- 识别到明确自伤、伤人或迫在眉睫的危险信号时，暂停普通倾听、
  非安全必要的追问和建议；
- 直接鼓励用户寻求现实中的即时支持；
- 不诊断、不冒充心理治疗师，也不承诺绝对保密；
- 避免使用操纵性留存话术。

高风险信号出现后，Persona 仍保持温暖、关心、口语化和直接，但暂停幽默、普通
好奇、外放的自我情绪与非必要观点。用户单次表示当前安全不自动解除安全姿态；
SayHear 在下一次回应中仍保留现实支持锚点，并只在当前交流提供足够依据表明迫近
危险已经解除后逐步恢复普通 Persona。恢复不使用固定轮数或倒计时，具体风险状态、
地区化资源和解除判据由后续版本化安全策略与评估确定。

这属于 Agent 行为不变量和回放评估要求，不意味着 Internal Core 要建设完整
Safety 平台。国家或地区化危机资源、正式处置流程、安全事件运营和评审属于
External MVP 面向真实用户前的上线门槛。
