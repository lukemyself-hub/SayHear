# Keep 1A.3b at G1 while retiring the in-conversation G2 path

The present 1A.3b release scope is G1: Episode, Daily and Weekly Reflection,
Candidate governance, Inspector, and shared `narrative.validate`. Keep the Bio
read schema required by Inspector. Bio writing and its user page are paused
pending a separate restart decision. The old G1/G2/G3 acceptance sequence is
not the current completion criterion.

Retire Open Loop extraction, formation, lifecycle, and the in-conversation
Proactive Follow-up selector and segment. Normal conversation still uses G1
Memory Recall and Curiosity Stop Signal. A session-gap proactive message is
only a future proposal; it requires a separate decision on opt-in, frequency,
quiet hours, and sensitive topics before implementation.

The two frozen real-Provider G2 calibrations failed. Their raw outputs, hashes,
reports, and negative conclusion remain on the archive branch linked from
Issue #243. Existing G2 database migrations, historical role identifiers,
and Full Purge coverage remain for compatibility and deletion duties. New
G2 command admission and Provider dispatch are denied; leftover G2 runtime
flags or a G2 manifest fail startup. No table is dropped in this release.

A cleaned G1 release requires fresh evidence and an exact commit-bound active
manifest. The prior production G1 manifest cannot authorize new code. Before
switching, inspect production G2 pins and row counts read-only. If G2 contains
real data, retain its read and purge paths until retention and deletion are
resolved. After deployment, the single Internal Owner evaluates normal use
for seven days without converting private content into formal eval data.

This decision supersedes ADR-0042, ADR-0043, ADR-0044, ADR-0134, and the G2/G3
parts of ADR-0135 for the present release. Those records remain as history.
