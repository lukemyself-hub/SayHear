# G2 v6 校准失败后的研究笔记

日期：2026-09-26。状态：研究资料，不是产品决定、SPEC 修订或新一轮校准授权。

## 这份资料回答什么

[Issue #243 的冻结报告](../../eval/continuation-acceptance-1a3b/issue-243-calibration-outcome.md)记录了两套合成开发集均失败：主回复经常已提出问题，Open Loop 目标未稳定形成，四类遗漏理由未稳定命中，低推理配置还有未归因的技术失败。下面只用原始论文和研究机构的正式论文讨论下一步值得验证的办法。论文中的系统、用户和任务与 SayHear 不同；表中的最后一列是**对 SayHear 的推断**，不是论文已证明的效果。

## 来源和可用结论

| 原始来源与研究设置 | 来源实际支持的结论和局限 | 对 SayHear 的推断 |
| --- | --- | --- |
| [Amershi 等，CHI 2019，Guidelines for Human-AI Interaction](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/01/Guidelines-for-Human-AI-Interaction-camera-ready.pdf)。18 条指南经过多轮评估，最终由 49 名设计从业者在 20 个 AI 产品上检验。 | 指南明确要求根据用户当前任务决定行动时机，避免不合时宜的打断；不确定用户目标时缩小服务范围或澄清。这是跨产品设计指南验证，**不是**对伴侣追问的效果试验。 | 把“主回复已提问或已覆盖目标”当作独立机会判断；一次回合的追问预算应跨主回复和 G2 共用。主回复已引导用户开口时，G2 不应再追加一个问题。 |
| [Brenna 等，Dialogue & Discourse 2025，Investigating Proactivity in Task-Oriented Dialogues](https://aclanthology.org/2025.dnd-16.2/)。人工标注英语、意大利语的多人任务对话，分析主动话语出现的位置和对话行为。 | 主动话语在对话回合中的分布并不均匀；论文报告其任务对话样本中约 20% 的回合为主动话语。语料不是伴侣对话，这个百分比**不能**成为 SayHear 的目标频率。 | 先标注当前回合功能和用户是否留下自然空档，再分析主动表达是否带来新增价值；不按固定追问率或每轮配额优化。 |
| [Maharana 等，ACL 2024，LoCoMo](https://aclanthology.org/2024.acl-long.747/)。以时间事件图驱动长对话生成，再由人工核对和编辑，评估长程问答、事件摘要等。 | 长对话里的时间与因果关系给模型带来困难；更长上下文或检索能改善部分任务，仍落后于人工。该基准主要测回忆与问答，**没有测**何时主动追问。 | Open Loop 的“谁说的、什么事、承诺何时有结果、结果是否未知”应作为可审计的事件字段和证据跨度检验，而非仅靠一句历史摘要触发。 |
| [Ge 等，Findings ACL 2025，TReMu](https://aclanthology.org/2025.findings-acl.972/)。在改造的 LoCoMo 多会话时间推理题上，以带日期的会话事件摘要和符号时间计算改善结果。 | 报告在其选择题设置下，GPT-4o 标准提示约 29.83，提出方法约 77.67。结果不能外推成 SayHear 的候选形成率，也不能证明应照搬符号执行。 | 单独检查 Event 提取、时间归一、待定状态和目标生成；用明确的目标真值定位是提取失败、证据缺失，还是时间门禁失效。 |
| [Qin 等，ACL 2021，TimeDial](https://aclanthology.org/2021.acl-long.549/)。约 1,100 个英文对话时间填空题，比较预训练模型与人工。 | 最优模型仍落后人工约 23 个准确率百分点，错误常依赖浅层时间线索。这是英文选择题，不是中英混合的待跟进事件抽取。 | 时间探针要覆盖相对日期、已过期、结果已知、时间矛盾及中英切换；不能只测显式“9 月 29 日会回复”。 |
| [Mai 与 Carson-Berndsen，ACL 2023，I already said that!](https://aclanthology.org/2023.acl-srw.33/)。在 BlenderBot 开放域对话上比较负例训练、解码和分类等办法。 | 作者报告组合方法把“用户已经答过却又问”的重复问题率从 27.2% 降到 8.7%。对象是模型生成的冗余问题，**不是**跨主回复与后置 G2 的系统级重复。 | 对主回复与候选 G2 问句增加语义重复判定，并用最小对照对测试：同一目标已在主回复问过、只提及未问、完全未提及。应把“语义重复”作为人工核验项。 |
| [Mizumoto 等，LREC-COLING 2024，问号对对话系统的影响](https://aclanthology.org/2024.lrec-main.435/)。研究语音识别文本中问号缺失对下游回复的影响。 | 问号的有无显著影响所研究系统的回复；口语问句可以没有问号。该论文不能证明任何特定的 SayHear 检测器有错。 | 机械问号检测只作诊断信号。对“想讲讲吗”“你起头”“要不要说说”等邀请、无问号问句和中英混合句，单独建立语义机会标签。 |
| [Geifman 与 El-Yaniv，ICML 2019，SelectiveNet](https://proceedings.mlr.press/v97/geifman19a.html)。在分类和回归数据上训练带拒答选项的选择性模型。 | 实验展示了覆盖率与已覆盖样本错误风险之间的取舍；不是 LLM 伴侣对话实验，也没有研究四种遗漏理由。 | 不要只优化 emit 数。并列记录“真正有机会且有足够证据时的 emit 率”和“不适合时的错误 emit 率”，画出覆盖与错误的关系。 |
| [Madhusudhan 等，COLING 2025，Abstain-QA](https://aclanthology.org/2025.coling-main.627/)。为黑箱 LLM 建立可回答与不可回答的混淆矩阵，比较严格提示、口头置信阈值和思维链。 | 即使较强模型也会在该问答基准上误拒答或误作答；一些提示策略改善了基准表现。问答拒答和 SayHear 的“是否自然插话”不同。 | 把 emit、正确 omit、错误 omit、技术失败四类分开计数。四个 omit 原因要有互斥的案例、反事实最小对照和人工语义复核；不能把“没调用模型”算成模型给对了理由。 |
| [Dwork 等，Science 2015，The reusable holdout](https://pubmed.ncbi.nlm.nih.gov/26250683/)。研究反复依据同一数据集结果调整分析方法的统计有效性。 | 适应性选择会让普通留出集验证失真；论文给出在特定统计假设下重复使用留出集的机制。它并没有评估 LLM Prompt 校准。 | #243 两套失败集可用于诊断，但后续根据它们调整 Prompt、样例或门禁时，它们就属于开发资料。新方案应预注册配置和停止规则，再用真正未看过的独立合成集验收；不能把修过的 #243 场景当新独立集。 |
| [Zheng 等，NeurIPS 2023，MT-Bench 与 Chatbot Arena](https://arxiv.org/abs/2306.05685)。比较 LLM 评委和人工偏好，并分析位置、冗长和自我偏好。 | 在其聊天回复偏好设置中，强模型评委与人工的一致率可超过 80%，但存在系统性偏差。它未验证 SayHear 的“自然接话”或遗漏理由。 | 可以用 LLM 评委协助筛查重复、时机和理由；对正式门禁仍需人工盲审和成对比较，并交换 A/B 顺序。机器评分不能替代真实语义判断。 |

## 建议优先验证的实验，而非直接改产品

1. **先做流水线归因。** 固定历史事件和目标真值，分别测试 Event 抽取、解析与校验、目标形成、时机门禁、主回复覆盖、选中目标、表达结果。每步记录输入、输出、失败类别和具体证据。现有 [`openLoopProposalCount`](../../eval/continuation-acceptance-1a3b/run-v6-capture.ts) 取自 `result.formedCount`，而 [Open Loop runner](../../packages/application/src/open-loop/runner.ts) 在 Provider 返回后还有证据、形成政策和容量校验。因此冻结记录能证明“未形成目标”，不能区分 Provider 根本没提出候选，还是提出后被校验拒绝。#243 已证明两轮失败不能单归因于 Prompt。
2. **给主回复和 G2 同一追问预算。** 当前 [`countFollowUpQuestions`](../../packages/application/src/conversation-behavior.ts) 只计 `?` 与 `？`，因此缺少标点的问句和邀请须单独核对。在表达调用前，人审主回复是否已问普通问题、已邀请用户开口、已询问同一目标，或当前任务要求先结束。用同一组冻结主回复做规则与语义检测的消融比较。若语义判断与机械判定分歧，先裁定样本，不通过放宽门禁来增加 emit。
3. **隔离四种 omit 理由。** 每个探针只改变一个条件。例如“证据不足”必须保留可选中目标和真实接话空档，仅删去可靠事实；“重复”只让主回复覆盖目标；“时机不自然”只加入用户转题或任务中断。预先定义当多个理由同时成立时如何裁定，不能让模型猜测出题人的意图。
4. **固定开发集与验收集边界。** 旧两套只用于发现错误和写回归用例。候选方案、全套 Provider 配置、阈值、人工判分规则和停止条件在新独立集合前冻结。报告完整分母，包括未到达 Provider 的回合、正确沉默、错误沉默和技术失败。
5. **让技术失败可诊断。** 对低推理配置先单独定位超时、schema、输出截断、拒绝或适配器错误，同时记录 token 用量和价格条件。#243 没保存足以区分这几种原因的细节，当前不能声称是某一种原因。即使修好技术故障，也仍需重过机会、候选和遗漏原因门禁。

这些实验只是研究建议。是否改变产品行为、现有 G2 门禁或 #243 之后的正式评测流程，应以当前 SPEC 与 ADR 为准，另行确认后实施。
